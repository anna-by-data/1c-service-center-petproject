# Техническое задание: учёт ремонтов сервис-центра (MVP)

## 1. Цель и контекст
Автоматизировать базовый операционный учёт сервисного центра на платформе 1С:Предприятие 8.3. Система должна обеспечивать ведение реестра заявок, автоматический расчёт стоимости ремонта, учёт остатков запчастей и взаиморасчётов с клиентами.

## 2. Функциональные требования

### ФТ-1. Документ «Заявка на ремонт»
* **Реквизиты шапки:**
  * `Клиент` (СправочникСсылка.Клиенты)
  * `Устройство` (Строка)
  * `ОписаниеНеисправности` (Строка)
  * `Мастер` (СправочникСсылка.Сотрудники)
  * `Статус` (ПеречислениеСсылка.СтатусыЗаявок: *Новая, В работе, Ожидание запчастей, Готова, Ожидает оплаты, Закрыта*)
  * `Сумма` (Число — итоговая сумма заявки, рассчитывается автоматически)
  * `Дата` и `Номер` (стандартные реквизиты, автозаполнение)
* **Логика статусов:** смена статусов выполняется вручную в документе по ходу выполнения работ. При проведении документа «Оплата от клиента» статус связанной заявки автоматически меняется на «Закрыта».

### ФТ-2. Автоматический расчёт сметы в заявке
* **Табличная часть «Работы»:**
  * `ВидРаботы` (СправочникСсылка.ВидыРабот)
  * `Количество` (Число)
  * `Цена` (Число — подставляется автоматически из справочника при выборе работы, доступна для редактирования)
  * `Сумма` (Число — рассчитывается автоматически: `Количество * Цена`)
* **Табличная часть «Запчасти»:**
  * `Запчасть` (СправочникСсылка.Запчасти)
  * `Количество` (Число)
  * `Цена` (Число — подставляется автоматически из справочника при выборе запчасти, доступна для редактирования)
  * `Сумма` (Число — рассчитывается автоматически: `Количество * Цена`)
* **Итоговый расчёт:** реквизит шапки `Сумма` автоматически пересчитывается как сумма колонок `Сумма` обеих табличных частей при любом изменении строк.

### ФТ-3. Учёт запчастей (Регистр накопления «Остатки запчастей»)
* **Вид регистра:** Остатки.
* **Измерение:** `Запчасть` (СправочникСсылка.Запчасти).
* **Ресурс:** `Количество` (Число).
* **Приход:** документ «Приход запчастей» при проведении формирует движение `Приход` по ресурсу `Количество`.
* **Расход:** документ «Заявка на ремонт» при проведении в статусе «Готова» формирует движение `Расход` по табличной части «Запчасти». Перед списанием выполняется проверка наличия достаточного остатка на складе.

### ФТ-4. Взаиморасчёты с клиентами (Регистр накопления «Взаиморасчёты с клиентами»)
* **Вид регистра:** Остатки.
* **Измерение:** `Клиент` (СправочникСсылка.Клиенты).
* **Ресурс:** `Сумма` (Число).
* **Начисление долга:** при проведении «Заявки на ремонт» в статусе «Ожидает оплаты» фиксируется движение `Расход` на сумму заявки.
* **Оплата:** документ «Оплата от клиента» при проведении формирует движение `Приход` на сумму оплаты и переводит статус заявки в «Закрыта».

### ФТ-5. Учёт прочих расходов и отчётность (СКД)
* **Документ «Расход»:** реквизиты `СтатьяРасхода` (ПеречислениеСсылка.СтатьиРасходов), `Сумма` (Число), `Комментарий` (Строка).
* **Отчёты на СКД:**
  1. **«Выручка и расходы»** — сравнение поступлений от клиентов и расходов за период.
  2. **«Остатки запчастей»** — текущее количество запчастей на складе.
  3. **«Долги клиентов»** — список клиентов с неоплаченными заявками.

## 3. Ограничения MVP (Out of Scope)
* В первой версии не реализуются: история изменения статусов, автоматическая постановка задач сотрудникам, программная блокировка редактирования строк и сложная матрица ролей.
* Учёт ведётся по одному основному складу.
